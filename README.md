# Delayed Notifier

Система отложенных уведомлений с поддержкой Telegram и Email каналов. 

(Доступна на данный момент отправка сообщений **только по Telegram**)

## Описание проекта

Delayed Notifier - это микросервис для планирования и отправки уведомлений в указанное время. Система поддерживает различные каналы доставки (Telegram, Email) и обеспечивает надежную доставку с механизмом повторных попыток.

## Архитектура

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   HTTP API      │    │   Worker        │    │   Queue         │
│   (Gin Router)  │────│   (Scheduler)   │────│   (RabbitMQ)    │
└─────────────────┘    └─────────────────┘    └─────────────────┘
         │                       │                       │
         │                       │                       │
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   PostgreSQL    │    │   Redis Cache   │    │   Telegram Bot  │
│   (Database)    │    │   (Status)      │    │   (Sender)      │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### Компоненты:

- **HTTP API** - REST API для создания и управления уведомлениями
- **Worker** - фоновый процесс для планирования и отправки уведомлений
- **Queue** - RabbitMQ для асинхронной обработки уведомлений
- **Database** - PostgreSQL для хранения уведомлений
- **Cache** - Redis для кэширования статусов
- **Sender** - модуль отправки через Telegram Bot API

## API Endpoints

### 1. Создание уведомления
**POST** `/api/notify/`

**Тело запроса:**
```json
{
  "message": "Текст сообщения",
  "send_at": "2025-09-26T23:45:00+03:00",
  "to": "680080262",
  "channel": "telegram",
  "retries": 3
}
```

**Поля:**
- `message` (string, обязательное) - текст уведомления
- `send_at` (string, обязательное) - время отправки в формате RFC3339
- `to` (string, обязательное) - получатель (Telegram ID или email)
- `channel` (string, обязательное) - канал доставки: `telegram` или `email`
- `retries` (int, опциональное) - количество попыток (по умолчанию 3)

**Ответ:**
```json
{
  "id": "1",
  "message": "Текст сообщения",
  "send_at": "2025-09-26T23:45:00+03:00",
  "to": "680080262",
  "channel": "telegram",
  "status": "pending",
  "retries": 3,
  "created_at": "2025-09-26T20:30:00Z",
  "updated_at": "2025-09-26T20:30:00Z"
}
```

### 2. Получение всех уведомлений
**GET** `/api/notify/`

**Ответ:**
```json
[
  {
    "id": "1",
    "message": "Текст сообщения",
    "send_at": "2025-09-26T23:45:00+03:00",
    "to": "680080262",
    "channel": "telegram",
    "status": "pending",
    "retries": 3,
    "created_at": "2025-09-26T20:30:00Z",
    "updated_at": "2025-09-26T20:30:00Z"
  }
]
```

### 3. Получение статуса уведомления
**GET** `/api/notify/:id`

**Ответ:**
```json
{
  "status": "sent"
}
```

### 4. Отмена уведомления
**DELETE** `/api/notify/:id`

**Ответ:**
```json
{
  "message": "Notification canceled successfully"
}
```

## Статусы уведомлений

- `pending` - ожидает отправки
- `sent` - успешно отправлено
- `failed` - не удалось отправить после всех попыток
- `canceled` - отменено пользователем

## Форматы данных для фронтенда

### Создание уведомления

**Обязательные поля:**
- `message` - текст сообщения (string)
- `send_at` - время отправки в формате ISO 8601: `2025-09-26T23:45:00+03:00`
- `to` - получатель:
  - Для Telegram: числовой ID пользователя (например: `680080262`)
  - Для Email: email адрес (например: `user@example.com`)
- `channel` - канал доставки: `telegram` или `email`

**Опциональные поля:**
- `retries` - количество попыток отправки (по умолчанию 3)

### Примеры запросов

**Telegram уведомление:**
```json
{
  "message": "Привет! Это тестовое уведомление",
  "send_at": "2025-09-26T23:45:00+03:00",
  "to": "680080262",
  "channel": "telegram",
  "retries": 3
}
```

**Email уведомление:**
```json
{
  "message": "Важное уведомление",
  "send_at": "2025-09-27T10:00:00+03:00",
  "to": "user@example.com",
  "channel": "email",
  "retries": 5
}
```

## Запуск проекта

### Требования
- Docker
- Docker Compose

### Переменные окружения
Создайте файл `.env`:
```env
DB_HOST=db
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=delayed_notifier
REDIS_PASSWORD=your_redis_password
TG_BOT_TOKEN=your_telegram_bot_token
```

### Запуск
```bash
docker-compose up -d
```

### Остановка
```bash
docker-compose down
```

## Логирование

Система использует структурированное логирование с уровнями:
- `info` - информационные сообщения
- `warn` - предупреждения
- `error` - ошибки

## Обработка ошибок

- При неудачной отправке система автоматически повторяет попытку
- После исчерпания всех попыток уведомление помечается как `failed`
- Уведомления со статусом `failed` или `canceled` не обрабатываются повторно
